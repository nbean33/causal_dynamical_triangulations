# `data/`: plot-ready JSON from the research repo

Every `.json` file here is generated by `tools/sync_from_cdt.py` from the read-only research repo `CDT_4d-master`. Do not edit them by hand. To regenerate:

```bash
python tools/sync_from_cdt.py ../CDT_4d-master
```

The script also copies the PNG fallbacks into `assets/fig/{lisp-validation,large-volume,curvature2d}/`. `manifest.json` records the source commit. This README is written by hand and the script never touches it.

## Conventions shared by all files
- **Compact JSON.** Floats have at most 6 significant digits, and history values 4. There are no `NaN`s: a missing or failed value is `null`. Every file loads with `fetch(...).then(r => r.json())`.
- **`code`.** Which simulation produced the run:
  - `"lisp"`: the corrected Lisp code `3p1_mh/`, from its first validation at small volume (`3p1_mh/validation/VALIDATION.md`);
  - `"cpp"`: the C++ code `cdt/4d`, from the large-volume validation (`cdt/validation/VALIDATION4D.md`).
- **`volume`.** A label such as `"5k"`, `"20k"` or `"80k"`. It is the target N41, the number of (4,1)+(1,4) simplices. Numeric `N41` and `N4` fields carry the measured averages.
- **Statistics triplet.** A field like `N0_N4: [mean, err, tau]` gives the mean, an error corrected for autocorrelation, and the integrated autocorrelation time τ_int in measurements.
- **`proposals`.** Metropolis–Hastings proposals counted from the start of the run, thermalisation included. `therm_end` is the proposal count at which production starts.
- **`arxiv`.** An arXiv identifier such as `0807.4481` or `hep-th/0505154`. Link it as `https://arxiv.org/abs/<id>`.
- **Fit fields** (`fit`, from `analysis.fit_desitter`):
  - `w`, `w_err`: the cos³ width in slices;
  - `s0`, `s0_err`: the width parameter using N4, which is the published convention;
  - `s0t`, `s0t_err`: the same using N41;
  - `chi2dof`, `npts`: fit quality and the number of points fitted;
  - `stalk`: the median N3 in the thin region;
  - `free_amp`, `free_w`, `free_chi2dof`: the fit with a free amplitude;
  - `norm_ratio`: free amplitude ÷ the normalised amplitude.

## `desitter.json`: phase C volume profile and scaling collapse
```text
published   {value: 0.59, N4_range: [45500, 362000], arxiv, target: "T2", curve: {x[], y[]}}
rescaling   {x: "i / N4^(1/4)", y: "<N3(i)> / (N41/2) * N4^(1/4)", model: "y = (3/4)/s0 cos^3(x/s0) ..."}
chains[]    one entry per Markov chain:
  id, code, volume, N41, N4, T, window ("second half of production"), nmeas
  start         "uniform" | "concentrated" | null
  equilibrated  false for lisp 10k and cpp 80k: plot them dashed or label them provisional
  i[]           slice index, centred so the centre of volume sits at i = 0 (AGJL centring)
  n3[]          mean N3(i) over the window
  x[], y[]      the same points rescaled: the collapse plot
  s0_2nd_half, norm_ratio_2nd_half    cpp only: the per-chain fit quoted in VALIDATION4D.md
fits[]      one entry per volume and code, a fit of the pooled profile over all of production:
  volume, code, N41, N4, nmeas, window, provisional
  fit           the fit fields above, or null (cpp 80k: see fit_error)
  curve         {x[], y[]}: the fitted cos³ in rescaled units (null when fit is null)
  curve_free_amp                cpp only: the free-amplitude fit in rescaled units
  s0_chains_all[], s0_chains_2nd_half[]   cpp only: s0 per chain
D_H_best_overlap {lisp, cpp: {value, volumes}, scan: [2.5, 6], note}
```
**Plot.** Draw `chains[].x`/`y` coloured by volume, with `published.curve` as the reference line.

**Which s0 to quote.** The write-ups quote the per-chain spread, not the pooled fit:
- 20k: chains 0.53, 0.52 and 0.64;
- 40k: the single-blob chains, 0.66 and 0.59.

The pooled 40k fit (1.05) and the pooled Lisp 10k fit (1.20) come from profiles that hold two blobs. Do not quote them as s0.

## `spectral.json`: spectral dimension D_S(σ)
```text
ajl         {a: 4.02, b: 119, c: 54, formula, arxiv, N4: 181000, fit_range: [40, 400],
             curve: {sigma[], ds[]}  (sigma = 10..800)}
sigma_min_reliable  40   (odd/even lattice artefacts below; shade or clip sigma < 40)
runs[]      the C++ runs (dual-graph diffusion, 20 sources per measurement):
  id ("spectral-20k"), run, code, volume, N4, nmeas, nsources, peak, sigma_peak
  blob        false for 80k: that geometry is not a de Sitter blob, so it does not test the AJL fit
  sigma[]     even sigma from 4 to 398 / 598 / 798
  ds[], err[] D_S and its jackknife error over measurements
  at          {"40": {ds, err, ajl}, ...}: the table in VALIDATION4D.md
  fit         {a, b, c, err[3], DS0}: a - b/(c + sigma) on 40..400. Not meaningful, because the curves turn over
lisp_peaks[] {volume, code, N4, nconfigs, nstarts, peak, sigma_peak}: the Lisp runs (N4 = 4.5k–22k)
```
The Lisp D_S curves are not included. Recomputing them needs diffusion on the saved configurations, and the research repo keeps only the peaks. Use `assets/fig/lisp-validation/spectral.png` for them.

## `phases.json`: phase diagram, phase B, the A–C transition
```text
published       {AC: {kappa0: 4.711, Delta: 0.6, N4: 120000, order, N0_N4_jump: [0.153, 0.163], arxiv},
                 BC: {Delta: 0.022, kappa0: 2.2, N4: 40000, order, arxiv},
                 examples: {A: [5.0, 0.0], B: [1.6, 0.0], C: [2.2, 0.6]}  ([kappa0, Delta])}
classification  "B if max_slice_frac > 0.5; else C if lag1 > 0.2; else A"
runs[]          every phase-scan run (Lisp ph*, k0s-*, dls-*; C++ phB-*, AC-*):
  id, code, kappa0, Delta, T, N41, start ("uniform"|"concentrated"|"collapsed"|null), nmeas
  N0_N4, conjD          [mean, err, tau]; conjD = (N41 - 6 N0)/N4, the B–C order parameter
  ext90                 consecutive slices holding 90% of the volume (mean)
  max_slice_frac        fraction of the volume in the largest slice (mean)
  lag1                  neighbour-slice correlation of the profile: about 0.8 for C, about 0 for A and B
  k4                    frozen kappa4
  mean_profile[]        centred mean N3(i) (thinned to <= 300 measurements)
  phase                 "A" | "B" | "C", from the classification rule
  stats_source          "summary.json" | "results.json" | "computed from out/*.meas (not in summary.json)"
kymographs      {run id: {stage: "TTT...PPP", proposals[], therm_end, profiles[[N3(0..T-1)], ...]}}
                48 raw (uncentred) profile snapshots over the whole run: draw as a heat map, time across,
                slice down. Runs: phA, phB, k0s-3.6, k0s-4.2, dls-0.0, phB20a-u, phB-20k-u-c0, phB-40k-u-c0,
                AC-20k-4.4-u-c0, AC-20k-4.8-u-c0
phaseB_collapse[] {id, code, N41, T, start, proposals[], value[], therm_end}
                value = largest slice / total volume, about 100 points spaced for a log proposals axis
AC_history[]    {id, code, kappa0, N41, start, phase, proposals[], value[], therm_end,
                 hist: {counts[20], edges[21]}}: value = N0/N4 (120 points, linear spacing);
                 hist is the production histogram of N0/N4
AC_vs_kappa0[]  {code, N41, runs[]}: run ids at Delta = 0.6, sorted by kappa0. Plot runs[id].N0_N4
                against kappa0 per series, with published.AC.N0_N4_jump as a band
```
**Plot ideas.**
- The C++ `phB-*-u` collapse curves against the Lisp `phB20a-u` / `phB20b-u`, which stay a blob.
- The A–C plot: N0/N4 jumps between C and A, and the jump moves to larger κ0 as N41 grows.

## `fluctuations.json`: ξ = N32/N41 and k1
```text
published   {xi: [{N41, N4_over_N41, xi, arxiv}]  (Ñ4 = 10k..160k, [R] Table 1),
             k1: {value: 0.038, arxiv, target}}
err_note    what the errors mean
xi[]        {id, code, volume, N41, xi, err, tau, equilibrated}: one entry per chain
k1[]        {volume, code, N41, k1, err, nbulk, nmeas}: err is the spread (sd) of k1_i over the nbulk bulk

```

## `curvature2d.json`: 2D quantum Ricci curvature (⟨d̄/δ⟩ profiles)
```text
cdt   2D CDT on the torus, against arXiv 2110.11100
  arxiv
  sets[]      {id, distance ("link"|"dual link"), sampler, N2, delta[], mean[], err[], nchains, nmeas,
               half_z_max, paper_cmp: {deltas[], paper[], diff[], z[], max_abs_diff, rms_z} | null}
              ids: link-50k, link-90k, link-150k (delta 1..30), dual-100k (1..60), bug-50k
              (bug-50k uses the original 2d-cdt sampler with its acceptance bug; paper_cmp is null)
  bug_vs_fixed {fixed: "link-50k", bug: "bug-50k", z[30], chi2_per_dof, max_abs_z, max_abs_diff}
  lattice_flat {link: {delta[], value[]}, dual: {...}, check_vs_paper}: exact flat-lattice reference
  paper       {fig5: {distance: "link", note, curves[]}, fig7: {distance: "dual link", curves[]}}
              curves[] = {label ("hexagonal"|"50k"|...), N2 | null, delta[], value[]}: the paper's
              points, digitised (reading accuracy about 0.0006)
dt    2D Euclidean DT on S², against arXiv 1802.10524
  arxiv, fit_rule
  runs[]      {N, delta[1..15], mean[], err[], nchains, nmeas,
               fits: {"D2+": {rho, err, chi2_per_dof, paper, z}, "D2x": ..., ... "D5x"},
               fit_curves: {"D2+": {delta[], value[]}, ...}}   (fitted sphere curve on delta = 2..15)
  scaling     {"D2+": {D_prime, err, volumes[], paper_table1_same_volumes, paper_table2}, ...}
  sphere_ref  {"2".."5": {x[], f[]}}: <d̄/δ> on a round D-sphere against x = δ/ρ
```
Fit keys are `D<dim><shift>`. The shift `+` is additive and `x` is multiplicative.

## `targets.json`: published targets
```text
source, refs[] {tag ("R"|"S"|"dS"|"Rev"), arxiv, citation}
conventions[]  {text, sub[]}: the simulation conventions of the papers
targets[]      {id ("T1".."T5"), title, refs (as written), arxiv[], items[] {label, text, sub[]}, text[]}
values         machine-readable numbers, each with arxiv and target:
  s0 {value, N4_range}; stalk {s, N3_per_slice}
  AC_transition {kappa0, Delta, N4, order, N0_N4_jump}; BC_transition {Delta, kappa0, N4, order}
  D_H {value, err}; D_S_fit {a, b, c, N4, sigma_range, D_S_inf [v, err], D_S_0 [v, err]}
  k1 {value}; xi [{N41, N4_over_N41, xi}]
```
The text fields are plain text, with markdown and links stripped. They contain Unicode (κ, Δ, σ, ≈, ±).

## `references.json`: bibliography
```text
source, categories[] {id ("A".."G"), name, count}
entries[]   {key ("arXiv:<id>" or e.g. "israel-lindner-2012"), title, authors[] ("J. Ambjorn" order),
             authors_short (from INDEX.md), year, arxiv | null, primary_class | null, doi | null,
             journal | null (arXiv journal-ref strings, e.g. "Phys.Rev.D76:104022,2007"),
             category, note | null (the relevance note; 159 of 239 have one)}
```
The entries are ordered by category, then as in `INDEX.md`. Local file paths are not included.

## Provenance
**Summary files read:**
- `3p1_mh/validation/summary.json` and `TARGETS.md`;
- `cdt/validation/large-volume/results.json`;
- `cdt/validation/2d-curvature/{results,results_dt,lattice_ref,sphere_ref,paper_figs}.json`;
- `references/references.bib` and `INDEX.md`;
- `notes/READING.md`.

**Measurement files read, never copied:**
- `*.meas`, `*.log` and `spectral_dual-*.dat` in `3p1_mh/validation/out/` and `cdt/validation/large-volume/out/`.

The script recomputes from these what the summaries leave out: profiles, the collapse, D_S(σ) and the histories. It uses the estimators of `3p1_mh/validation/analysis.py`. As a check, it refuses to write if it disagrees with the summaries:
- D_S at the tabulated σ;
- the production counts;
- N0/N4 of the 12 Lisp runs in `summary.json`.
