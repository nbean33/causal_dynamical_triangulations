Sampler audit

Summary

The geometry in the legacy 4D code is correct, but its Monte Carlo sampler does not satisfy detailed balance and therefore samples a different distribution from the intended one. Smaller errors of the same kind were found in the upstream 2D and 3D codes.

Correctness criterion

A CDT simulation should visit each triangulation \(T\) with probability proportional to \(e^{-S[T]}\). The standard way to guarantee this is detailed balance: in equilibrium, the flow from \(T\) to \(T'\) equals the flow back,

$$e^{-S[T]}\; q(T\to T')\; a(T\to T') \;=\; e^{-S[T']}\; q(T'\to T)\; a(T'\to T),$$

where \(q\) is the probability that the code proposes a move and \(a\) the probability that it accepts it. The Metropolis–Hastings rule \(a = \min\big(1,\, R\, e^{-\Delta S}\big)\) with \(R = q(T'\to T)/q(T\to T')\) satisfies this. Omitting \(R\) is correct only if every move and its inverse are equally likely to be proposed, which is rarely the case in CDT.

Detailed balance can be checked exactly. On a small triangulation, enumerate every random draw the code could make, count how many lead to each move instance, apply the move, and repeat the count for the inverse in the new triangulation. This gives \(R\) exactly for every instance, for comparison with the factor used by the code. This procedure, referred to here as the kernel test, identified every error described on this page.

The legacy 4D Lisp code

The audit covered the 3+1-dimensional Lisp code by Rajesh Kommu (3p1/). The sources were not modified; every check was run on the code as distributed, in SBCL under Docker.

Geometry

An independent checker recomputed all derived data from the list of simplices alone: simplex types and times, every tetrahedron shared by exactly two pentachora, symmetric neighbour pointers, the sub-simplex tables, the counts, Euler characteristic zero, and every spatial slice a closed 3-manifold. It was run after every move in stress tests of all ten move types, over 10,000 mixed moves and over Metropolis sweeps. No invariant violation was found. The change in counts of every move satisfies both 4D Dehn–Sommerville relations, and the action coefficients match the AJL action exactly.

B1. No Hastings factor (critical)

The code drew a random simplex id and a random move type, and re-drew until a move was possible. Exact enumeration of all 7,100 draws on a configuration with \(N_4 = 700\) gives the true ratio \(R\) for each move type:

The code used \(R = 1\) for all of them. For (2,8)/(8,2), \(R\) is a constant 4, because a (2,8) site is reached from its 2 pentachora while the inverse (8,2) site is reached from all 8. This alone is equivalent to sampling at an effective \(\kappa_0\) shifted by \(-\ln 4 \approx -1.39\). For the other moves \(R\) depends on the local configuration, so the effect is not a simple shift of the couplings: the code samples an uncontrolled reweighting of \(e^{-S}\).

The same sweep design is used in the 2+1-dimensional Lisp codes in the repository, so the problem is not confined to the 4D code.

B2. Failed proposals re-drawn (high)

78% of draws fell on a site where no move was possible and were re-drawn rather than counted as rejections. This conditions the chain on the move being possible, which changes the proposal probabilities in a way that depends on the whole configuration. It also means that the reported acceptance rates were not true acceptance rates.

B3. First-found candidate and irreversible moves (critical)

Each move search returned the first valid candidate in list order, rather than a random one. Valid moves preceded by another candidate are never proposed from that starting simplex. In a test of 300 (4,6) moves, 3 (1%) could not be reversed: after the move, every one of the six new pentachora found a different (6,4) candidate first. A move whose inverse has zero proposal probability violates detailed balance directly.

B4. Wrong pair enumeration (medium)

A helper meant to iterate over all pairs of neighbours returned only cyclic pairs: for \((a, b, c, d)\) it gave \((a,b), (b,c), (c,d), (d,a)\) and never \((a,c)\) or \((b,d)\). With five neighbours, 5 of the 10 pairs were skipped. The correct helper already existed in the same utilities file.

B5. Volume fixing fails (high)

The code held the volume with a linear penalty \(0.02\,|N_4 - V|\). This can work only if \(\kappa_4\) is within about ±0.02 of its pseudo-critical value. At \((\kappa_0, \Delta) = (2.2, 0.6)\), \(\kappa_4 = -0.2\) made \(N_4\) grow from 4,000 to 83,910 in 30 sweeps, and \(\kappa_4 \ge 0.1\) collapsed it to the minimal spacetime. No extended universe could be observed.

Smaller findings
  • B6. The random id was drawn from \(0\ldots\text{max}-1\), which includes unused ids and can never pick the newest simplex.
  • B7. Acceptance probabilities in single precision (24-bit), and an RNG seeded from the clock and never saved, so runs could not be reproduced.
  • Initialisation. T = 2 gives a degenerate complex and odd T is silently wrong; there is no input check.
  • Safety. Every file compiles with (safety 0), so a memory error would produce incorrect data rather than an error message.
  • Observables. Off-by-one random indices and loop bounds in the C++ diffusion codes, and a non-lazy random walk that makes even and odd diffusion times oscillate.

The corrected sampler

The corrected code (3p1_mh/) keeps the move geometry unchanged and replaces the sampler:

FindingFix
B1, B6: random ids with holesO(1) site bags of (4,1)/(1,4) and (3,2)/(2,3) simplices, with uniform pick, add and remove.
B2: failed draws re-drawnOne site per proposal. If the site carries no valid move, the proposal counts as a rejection.
B3: first-found candidateEach draw names the move's centre, the sub-simplex it removes. A Pachner move is fixed by its centre, so there is at most one candidate per draw.
B1: no Hastings factor\(a = \min\big(1,\ C_m(T)/C_{\text{rev}}(T')\; e^{-\Delta S}\big)\), with the site counts \(C_m\) derived per move type.
B4: cyclic pairsIteration over all pairs and triples.
B5: linear volume fixingQuadratic fixing \(\varepsilon\,(N_{41} - \bar V)^2\) and adaptive \(\kappa_4\) during thermalisation only.

The resulting Hastings factors are simple. For example, (2,8) gets \(N_{41}/(N_{41}+6)\), (8,2) gets \(N_{41}/(N_{41}-6)\), (4,6) gets \(N_{41}/(N_{41}+2)\), and the v1 (2,4), (4,2) and (3,3) moves get exactly 1.

Verification. The kernel test, enumerating every draw on three configurations, checked more than 2,300 move instances of all ten types. For every one, the exact ratio \(R\) equals the factor the sampler uses, with \(|R/H - 1| \le 2\cdot10^{-15}\), and no move is irreversible. With quadratic volume fixing, chains started at \(\kappa_4 = 0\) and \(\kappa_4 = 1.5\) both reach the target volume within 15 sweeps and settle at the same \(\kappa_4\).

The upstream 2D and 3D codes

For the unified C++ codebase, built from JorenB's 2d-cdt and 3d-cdt, the kernel test was ported to C++ and applied to these codes as well. Their design follows the methods paper of Brunekreef, Görlich and Loll (2310.16744). The test found four errors in the acceptance ratios:

CodeErrorEffect
3D add / deleteThe add move picks a (3,1)-simplex and its inverse picks a vertex, so the correct ratio is \(N_{31}/(N_0+1)\), as in eq. (26) of the methods paper. The code used \(N_{31}/(N_{31}+2)\), and the corresponding wrong factor for delete.Add was under-accepted about 2×, so the code effectively simulated \(k_0 - \ln 2\). The tuned \(\kappa_3\) at \(k_0 = 5\) moves from 1.641 to 1.812 when fixed, a shift of 0.171 against the predicted \(\ln 2/4 = 0.173\).
2D delete at the target volumeAt \(N_2 = \bar V\) a delete increases the penalty \(\varepsilon|N_2 - \bar V|\), so the factor should be \(e^{-2\varepsilon}\); the code used \(e^{+2\varepsilon}\) (a < that should have been <=).These deletions were over-accepted by \(e^{4\varepsilon} = 1.083\).
3D delete and inverse shift, volume termsTwo volume-fixing expressions had a sign flipped.Off by \(e^{8\varepsilon}\), \(e^{32\varepsilon}\) and \(e^{2\varepsilon}\); negligible at the default \(\varepsilon\), but incorrect.

The port also showed that the upstream codes initialised every random engine with seed 0 and reseeded only one of them from the configuration. The engine that selects move sites therefore produced the same sequence for every seed.

For published results, the effect of the 2D error was checked directly: the curvature profile of arXiv:2110.11100, recomputed with the original sampler, agrees with the corrected one (\(\chi^2/\text{dof} = 1.13\)), so those results are unaffected. The 3D shift of \(k_0\) by \(\ln 2\) is larger, and results obtained with the original 3d-cdt correspond to a different effective \(k_0\) from the configured value.

Remark. Statistical checks, such as comparisons of averages with known results, can miss sampler errors of this size, particularly when the error is equivalent to a shift in a coupling that is tuned in any case. An exact kernel test detects such errors directly and is inexpensive to run.
