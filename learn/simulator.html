The model

Space is one-dimensional and closed (a circle), and time is periodic, so spacetime has the topology of a torus. Each horizontal row in the display is a spatial slice at fixed time, and every triangle spans one time step, as in the figure on the introduction page. The lengths of the slices change as triangles are added and removed; these are the fluctuations of the spatial volume.

The plot shows the volume profile, the length of each slice, together with its running average. In 2D the average profile is flat, with large fluctuations; the de Sitter profile discussed elsewhere on this site arises only in 4D. The 2D model is nevertheless useful for illustrating the method, because it is small enough to display and can be solved exactly, which allows the code to be checked.

Algorithm

The simulation samples triangulations \(T\) with weight \(e^{-\lambda N_2(T)}\), where \(N_2\) is the number of triangles and \(\lambda\) the cosmological constant. Each step selects one of three moves and a location, and accepts the proposal with the Metropolis–Hastings probability. The acceptance ratios include the Hastings factors required for exact sampling:

$$a_{\text{add}} = \min\!\left(1,\ \frac{N_0}{N_{\text{vf}} + 1}\, e^{-2\lambda}\right), \qquad a_{\text{delete}} = \min\!\left(1,\ \frac{N_{\text{vf}}}{N_0 - 1}\, e^{2\lambda}\right), \qquad a_{\text{flip}} = \min\!\left(1,\ \frac{w_a}{w_b}\right),$$

where \(N_0\) is the number of vertices, \(N_{\text{vf}}\) the number of vertices of order four (the possible locations of a delete move), and \(w_a\), \(w_b\) the numbers of flippable triangle pairs before and after the flip.

To hold the volume near a target \(\bar V\), each ratio is multiplied by \(e^{\pm 2\varepsilon}\) according to whether the move brings \(N_2\) closer to or further from \(\bar V\). The simulation starts at \(\lambda = \ln 2\), the critical value of 2D CDT, where this penalty can hold the volume.

Observations

  • Individual moves. At low speed, or with Step one move, individual additions, deletions and flips can be followed. The counters show the fraction of proposals accepted for each move.
  • Volume fixing. The number of triangles fluctuates around the target; the penalty \(\varepsilon\,|N_2 - \bar V|\) limits the deviation.
  • Dependence on \(\lambda\). The linear penalty is weak (\(\varepsilon = 0.02\)) and holds the volume only while \(\lambda\) is within about \(\varepsilon\) of \(\ln 2\). For \(\lambda\) above about 0.72 the volume decreases towards the minimum allowed; below about 0.66 it grows without bound, and the simulation pauses once it exceeds five times the target. The same limitation prevented the legacy 4D code from holding its volume (audit, B5), which is why the corrected code uses a quadratic penalty.
  • Slices to scale. With this option, the width of each row is proportional to the length of the corresponding slice.
  • Average profile. Individual profiles are highly irregular. Their average, aligned on the centre of volume, converges to a smooth shape with a characteristic spread, which can be computed exactly in 2D CDT.
Details: origin of the code

The simulator is a JavaScript port of the 2D part of the C++ codebase described on the code page, which derives from 2d-cdt by Joren Brunekreef and Andrzej Görlich (MIT licence). It includes the correction to the delete move: at \(N_2 = \bar V\) the original code multiplied by \(e^{+2\varepsilon}\) where the correct factor is \(e^{-2\varepsilon}\), over-accepting these deletions by \(e^{4\varepsilon} \approx 1.083\). The audit page describes how an exact test of the acceptance ratios identified it.
